# Python Concepts used in MedSynth

This guide maps core computer science and Python concepts directly to the MedSynth source code. It is designed to help you defend the technical implementation of the project.

### 1. Object-Oriented Programming (Classes & Objects)
* **Concept:** A `class` is a blueprint. An `object` is a specific instance of that blueprint.
* **Where in MedSynth:** `patient.py` defines the `Patient` class. When the generator runs, it creates thousands of distinct `Patient` objects in memory.
* **Why we use it:** To encapsulate the data (age, sex) and behaviors (aging) of a human being securely.

### 2. Composition (Has-A Relationship)
* **Concept:** Building complex classes by giving them instances of other classes as attributes.
* **Where in MedSynth:** The `Patient` class has a `record` attribute, which is an instance of `HealthRecord`. (A Patient *has a* HealthRecord).
* **Why we use it:** It keeps the biological simulation logic separate from the medical paperwork logic.

### 3. Generators and `yield` (Lazy Evaluation)
* **Concept:** Instead of creating a massive list and returning it all at once, `yield` returns items one by one, pausing the function until the next item is requested.
* **Where in MedSynth:** `generator.py` uses `yield patient` inside `generate_stream()`.
* **Why we use it:** To prevent Out-of-Memory (OOM) crashes. By yielding, `cli.py` can immediately write the patient to disk and delete them from RAM before requesting the next one.

### 4. Multiprocessing
* **Concept:** Using multiple CPU cores simultaneously by spawning separate OS processes.
* **Where in MedSynth:** `generator.py` uses `concurrent.futures.ProcessPoolExecutor`.
* **Why we use it:** Python's Global Interpreter Lock (GIL) prevents standard threads from running Python code in parallel. `ProcessPoolExecutor` bypasses the GIL, cutting generation time significantly.

### 5. File I/O (Input/Output) and Buffering
* **Concept:** Reading from and writing to the hard drive.
* **Where in MedSynth:** The Exporters (`csv_exporter.py`, `fhir_exporter.py`).
* **Why we use it:** We use `.flush()` to ensure data sitting in Python's memory buffer is physically written to the hard drive before a Checkpoint is saved.

### 6. Serialization (JSON & Pickle)
* **Concept:** Converting an object in memory into a string or byte format that can be saved or sent to another program.
* **Where in MedSynth:** 
  * `fhir_exporter.py` converts Python dictionaries to JSON strings using `json.dump`.
  * The `ProcessPoolExecutor` uses Python's internal `pickle` module to serialize the `Generator` object and send it to the worker processes.

### 7. Deterministic Randomness (Seeding)
* **Concept:** A computer's random numbers are not truly random; they are generated by a mathematical formula starting from a "seed". If you provide the same seed, you get the exact same sequence of "random" numbers.
* **Where in MedSynth:** `cli.py` uses `--seed 42`. The `Generator` uses `random.Random(seed)` to give every patient their own dedicated random number generator.
* **Why we use it:** For scientific reproducibility. A researcher in London and a researcher in Lagos will generate the exact same synthetic patients if they use the same seed.
